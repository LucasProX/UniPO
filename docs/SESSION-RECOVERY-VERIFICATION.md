# iOS 登录恢复与凭据一致性

日期：2026-10-21。关联 DP05（登录核心流程）与 DP21（客户端回归）的增量交付。完整开发范围继续以 [DEVELOPMENT-PLAN.md](DEVELOPMENT-PLAN.md) 为准；不新增 Web 用户端开发。

## 本轮验收规则

| 场景 | 必须满足的行为 |
| --- | --- |
| 正常启动 | 服务端验证身份后才显示登录状态，不把缓存资料当认证成功 |
| 网络、5xx、解码失败 | 保留凭据，允许重试，不自动删除或无依据刷新 |
| 新格式 access 返回 401 | 最多刷新一次；刷新明确 401 才清除被拒绝凭据 |
| Keychain 不存在与暂不可用 | 分别显示访客和可重试错误，不混为一谈 |
| 同时恢复、退出或换号 | 合并恢复请求；旧成功、失败和忙状态清理不能影响新身份 |
| 退出 | 本地私人身份立即清理，远端撤销使用旧凭据快照 |
| 保存凭据 | access/refresh 原子配对；写入失败不得显示登录成功 |
| 旧条目迁移 | 服务端校验 access/refresh 用户一致；无法确认旧配对时要求重新登录 |
| 删除旧条目失败 | 持久退出标记仍阻止旧账号恢复；清理失败可以重试 |
| HTTP 非 2xx | 不因正文出现 OK 或合法 data 而误报成功，不展示原始 HTML 错误页 |

## 当前证据

- Core 全部 69 项测试通过：其中 AuthStore 30 项、APIClient 14 项、凭据存储 14 项，其余为既有环境、分页和主页测试。
- 时序测试用 continuation 控制请求和 token setter 的返回，覆盖新登录前后两种迟到时序；使用内存存储与 URLProtocol，不读写用户真实凭据。
- 存储测试验证单条配对、旧格式迁移标记、持久退出标记、读写错误、部分删除失败和 Store 重建。
- iOS Debug 构建通过，已安装并通过 `simctl launch` 启动到既有 iPhone 17 / iOS 26.5 模拟器。Mac 当前锁屏，已请用户手动解锁；本轮新逻辑的冷启动恢复与重试提示尚未通过 UI 观察，不能据此写成界面验收完成。
- 单元测试不代替系统 Keychain 的实际持久化、最低系统与真机结果。

## 剩余工作与边界

DP05 仍需正式协议、真实登录供应商和 Release 通道；DP21 仍需 iOS 自动化旅程、最低系统和真机覆盖。本轮不把这些工作包标为完成。

服务端用户级和设备级身份吊销、Cookie 索引续期与既有 WebSocket 的权限复验仍未实现；代码证据及复现计划见 [DP02-IDENTITY-AUDIT.md](DP02-IDENTITY-AUDIT.md)。本轮没有修改或部署后端。Keychain 完全不可写时，持久退出清理仍须等存储可用后重试，界面会保留错误，不报告清理成功。

下一阶段先在隔离依赖复现 DP02，再用 ADR 确认用户身份版本、设备会话、故障语义和 WebSocket 失效上界，最后执行两设备、两实例 Redis 的验收。校园试点、运营指标和扩展门槛继续保留，尚未开始外部试点。
