# DP03 拉黑与社交一致性验收记录

记录日期：2026 年 10 月 22 日。当前状态为验证中。范围包含原生 iOS、服务端社交和内容权限、私信及实时投递；本期不新增 Web 页面。

## 已实现的规则

只要任一方拉黑另一方，双方的关注、作品和私信能力受服务端限制。拉黑删除双向关注，取消拉黑恢复内容访问，但不恢复关注关系；朋友仍由真实双向关注决定。回复评论同时检查父评论作者，拒绝时不新增评论、计数或经验。

私信创建、发送及历史读取与关系变更共用 V22 的用户对锁。不同用户对有独立锁记录。提交顺序决定重叠请求的结果：私信先取得锁时可先完成；拉黑先提交时，等待它的私信请求必须拒绝。已经返回或进入传输的内容不能撤回。

会话列表在预览、用户资料及未读统计准备后，再通过社交 facade 批量查询权威关系。最终查询之前已提交的拉黑会隐藏对应结果；之后的响应属于在途。未读使用数据库分组计数，不读取所有未读正文。权威读取不得沿用业务事务的旧快照或 MyBatis 缓存。

私信 WebSocket 与 APNs 在消息同事务保存的持久 Outbox 中排队，独立 worker 在提交后投递，回滚不通知。私信不消耗 replay 序号、不进入通用缓存；重连后通过每次鉴权的消息 HTTP 接口同步。V23/V24 的恢复、小连接池与分设备进度证据见 [DP14 验收记录](DP14-VERIFICATION.md)。
