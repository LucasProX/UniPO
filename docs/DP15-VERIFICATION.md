# DP15 消息分页与发送重试验收记录

记录日期：2026 年 10 月 23 日。当前状态为验证中。后端、iOS Core 和模拟器 Debug 构建已有通过证据；服务器部署、登录后人工 UI、iOS 17、真机和真实 APNs 尚未验收。

## 已形成的实现

V25 为消息增加发送者范围内唯一的 `client_message_id`，为历史消息、未读聚合和会话两侧活动排序增加索引。会话列表使用绑定用户和完整排序键的游标；历史消息使用绑定用户与会话的排他游标。断线补齐通过 `afterId` 向前扫描，并在首个请求固定本轮最大消息 ID，避免活跃会话让一次恢复永不结束。

相同用户以相同 `clientMessageId`、会话和正文重试时返回第一次保存的消息，不更新会话时间，也不重复创建 Outbox 意图。相同标识被用于另一正文或会话时返回 HTTP 409 / `STATE_CONFLICT`。旧客户端不传该字段时继续按独立消息处理。

iOS 会话和消息改用分页接口。首屏、更多会话、历史消息和断线同步分别维护加载与错误状态；历史插入不强制滚到底部。发送时生成稳定标识并显示发送中状态，响应不确定时保留失败气泡，由用户明确重试或放弃。重试沿用原标识；后续 HTTP 同步若已看到同一标识，会消除待重试气泡。账号未知时不展示私人内容，同一账号验证恢复后才恢复草稿和待确认发送，换号或明确退出清理。

Outbox 增加 ADMIN 专属失败记录分页与单条重试接口。重试仅允许 FAILED 转为 PENDING，并以 `expectedAttempts` 防止覆盖新状态；状态变更与必需审计同事务提交。命令行工具只调用 API，不直接连接业务库。

| 项目 | 做法 | 结果 |

| 未读 | 退出会话回到列表 | 会话未读与底栏角标清零 |

验收中发现并修复：

1. 消息页会话行点不开、顶部「正在确认登录状态…」一直不消失。根因是 RootView 每次刷新都读 `UIWindow.safeAreaInsets` 摆底栏，SwiftUI 的新画面没有提交到屏幕，点击却按新布局判定。改为从 `GeometryReader` 读安全区，提示条移入页面 `VStack`。
2. 打开对话后底栏盖住输入框：对话打开时收起底栏，回到列表再显示。
3. 退出会话后未读数不清零：服务端已标记已读，但列表仍显示进入前的旧数，退出时重新拉取会话列表。
